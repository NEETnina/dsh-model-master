# 安全策略

## 报告漏洞

请**不要**用公开 issue 报安全问题。两种方式任选：

1. 用 GitHub 的 [私密漏洞报告](https://github.com/NEETnina/dsh-model-master/security/advisories/new)（推荐）
2. 邮件到维护者：见 commit 里的作者邮箱

请附上：影响版本、复现步骤、以及你能提供的日志片段。会尽快确认并给出修复计划。

## 本项目的安全边界（便于你判断什么算漏洞）

| 设计             | 说明                                                                                                                                                                                |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 只监听本机       | 所有 `/api/model-master/*` 路由都有 loopback 围栏（`isAuthorized()`）：只接受 `localhost` / `127.0.0.1` / `::1` 的 Host，并校验 `Origin`；`localhost.evil.com` 这类前缀伪造会被拒绝 |
| 不接触密钥       | 测速走 DSH 自己的 LLM provider 运行时，插件本身**不读、不存、不打印任何 API key**                                                                                                   |
| 无遥测           | 不收集、不上报任何使用数据                                                                                                                                                          |
| 对外请求只有两处 | ① `openrouter.ai/api/v1/models`（榜单数据源，10 秒超时 + 去重 + 限频）② 版本检查（`api.github.com` 与其无配额回退源），都不带任何标识信息                                           |
| 本地文件         | 只写 `$DSH_HOME/model-master/` 下的三个 JSON（榜单快照 / 测速结果 / 版本检查结果）                                                                                                  |

因此，**「插件能访问我的密钥吗」「会不会把数据发出本机」这类问题的答案是不会** —— 如果你发现了能绕过上述边界的路径（例如绕开 loopback 围栏、或让插件把密钥写进日志），那就是有效漏洞，请按上面的方式报告。
